# Spec Delta

## Purpose

bot のデータを単一ホスト上の SQLite に保存しつつ、ホストやディスクを失っても外部オブジェクトストレージから復元できる状態を保つ。

## ADDED Requirements

### Requirement: 起動時のマイグレーション
bot は Discord に接続する前に、未適用のスキーママイグレーションを DB に順番どおり適用しなければならない（SHALL）。マイグレーションが失敗した場合、DB をマイグレーション前の状態に保ったまま非 0 で終了しなければならない（MUST）。

#### Scenario: 空の DB から起動
- **WHEN** DB ファイルが存在しない状態（復元対象のレプリカもない）で bot を起動する
- **THEN** DB ファイルが作成され、すべてのマイグレーションが適用されてから Discord に接続する

#### Scenario: 適用済みの DB で再起動
- **WHEN** すべてのマイグレーションが適用済みの DB で bot を再起動する
- **THEN** マイグレーションは再適用されず、既存データはそのまま残る

#### Scenario: マイグレーションが失敗
- **WHEN** 適用途中で失敗するマイグレーションがある
- **THEN** bot は Discord に接続せず非 0 で終了し、DB はそのマイグレーションの適用前の状態のままである

### Requirement: 再起動をまたぐ永続化
bot が書き込んだデータは、コンテナの再作成やイメージの更新をまたいで保持されなければならない（SHALL）。

#### Scenario: イメージを更新して再作成
- **WHEN** データを書き込んだ後、新しいイメージでコンテナを再作成する
- **THEN** 書き込んだデータが新しいコンテナから読み出せる

### Requirement: 外部ストレージへのレプリケーション
DB への変更は、外部のオブジェクトストレージへ継続的に複製されなければならない（SHALL）。変更が確定してから複製されるまでの遅延は 1 時間以内でなければならない（MUST）。bot を停止するときは、停止前に確定した変更をすべて複製してから終了しなければならない（MUST）。

#### Scenario: 書き込みの複製
- **WHEN** DB に書き込みが確定する
- **THEN** 1 時間以内にその変更がオブジェクトストレージ上のレプリカに反映される

#### Scenario: 停止直前の書き込み
- **WHEN** DB に書き込みが確定した直後に、コンテナを停止する
- **THEN** 停止が完了した時点で、その変更がレプリカに反映されている

### Requirement: 失われた DB の自動復元
起動時に DB ファイルが存在せず、オブジェクトストレージにレプリカが存在する場合、bot はマイグレーションと Discord への接続より前に、レプリカから最新の状態を復元しなければならない（SHALL）。DB ファイルが存在する場合は復元してはならない（MUST NOT）。

#### Scenario: ボリュームが失われた
- **WHEN** データボリュームを削除してから bot を起動する
- **THEN** レプリカから DB が復元され、削除前に複製済みだったデータが読み出せる

#### Scenario: DB が存在する
- **WHEN** DB ファイルが存在する状態で bot を起動する
- **THEN** レプリカからの復元は行われず、手元の DB がそのまま使われる

### Requirement: 復元手順の文書化
リポジトリには、任意の時点への復元を含む、レプリカから DB を手動で復元する手順が文書化されていなければならない（SHALL）。

#### Scenario: 手順どおりに復元できる
- **WHEN** 運用者が文書の手順に従い、別のディレクトリにレプリカから DB を復元する
- **THEN** 復元された DB が開け、複製済みのデータが読み出せる
