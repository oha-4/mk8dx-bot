# Spec Delta

## Purpose

コマンドやメッセージリスナーの実行中に起きたエラーを、利用者に伝えるべき想定内のエラーと開発者が調査すべき想定外のエラーに振り分け、それぞれ適切な相手に届ける。

## ADDED Requirements

### Requirement: 想定内エラーの利用者への応答
機能が利用者向けのメッセージを持つ想定内エラーとして失敗を通知した場合、bot はそのメッセージを利用者に応答しなければならない（SHALL）。スラッシュコマンドでは実行者にのみ見える形で、プレフィックスコマンドでは元のメッセージへの返信として応答する。プレフィックスコマンドの返信では、実行者にメンションの通知を送ってはならず（MUST NOT）、元のメッセージが削除されていても応答を投稿しなければならない（SHALL）。想定内エラーはエラーログチャンネルに通知してはならない（MUST NOT）。

#### Scenario: スラッシュコマンドでの入力不備
- **WHEN** スラッシュコマンドが利用者向けメッセージ「プレイヤーが見つかりません」を持つ想定内エラーで失敗する
- **THEN** 実行者にのみ見える形で「プレイヤーが見つかりません」と応答し、エラーログチャンネルには何も送られない

#### Scenario: プレフィックスコマンドでの入力不備
- **WHEN** プレフィックスコマンドが利用者向けメッセージ「プレイヤーが見つかりません」を持つ想定内エラーで失敗する
- **THEN** 元のメッセージへの、メンション通知を伴わない返信として「プレイヤーが見つかりません」と応答し、エラーログチャンネルには何も送られない

### Requirement: 想定外エラーの利用者への応答
コマンドの実行が想定内エラー以外の理由で失敗した場合、bot は内部情報を含まない汎用のエラーメッセージを、想定内エラーと同じ方法で利用者に応答しなければならない（SHALL）。スラッシュコマンドでは、応答済みまたは応答保留中のインタラクションであっても、利用者に結果が届かないまま放置してはならない（MUST NOT）。

#### Scenario: 応答前に例外が発生する
- **WHEN** スラッシュコマンドが応答前に想定外の例外を投げる
- **THEN** 実行者にのみ見える汎用エラーメッセージが返り、例外メッセージやスタックトレースは含まれない

#### Scenario: 応答保留後に例外が発生する
- **WHEN** スラッシュコマンドが応答を保留（defer）した後に想定外の例外を投げる
- **THEN** 保留中の応答が汎用エラーメッセージで完了する

#### Scenario: プレフィックスコマンドで例外が発生する
- **WHEN** プレフィックスコマンドが想定外の例外を投げる
- **THEN** 元のメッセージへの返信として汎用エラーメッセージが返る

### Requirement: リスナーのエラーは利用者に応答しない
メッセージリスナーの実行が失敗した場合、bot は利用者に応答してはならない（MUST NOT）。ただし、想定外のエラーはエラーログチャンネルに通知しなければならない（SHALL）。

#### Scenario: リスナーで例外が発生する
- **WHEN** メッセージリスナーが通常メッセージの処理中に想定外の例外を投げる
- **THEN** 投稿者への返信は行われず、エラーログチャンネルに通知が届く

### Requirement: 想定外エラーの開発者への通知
コマンドまたはメッセージリスナーの実行が想定外の理由で失敗した場合、bot は設定されたエラーログチャンネルに通知を送り、スタックトレースをテキストファイルとして添付しなければならない（SHALL）。通知には、エラーの種類とメッセージ、実行場所（ギルドとチャンネル）、発生時刻を含め、さらにスラッシュコマンドではコマンド名と指定されたオプションを、プレフィックスコマンドとリスナーでは元のメッセージ本文を含めなければならない（SHALL）。

#### Scenario: スラッシュコマンドの例外の通知
- **WHEN** `/ping` の実行中に想定外の例外が発生する
- **THEN** エラーログチャンネルに、エラーの種類・メッセージ・コマンド名・オプション・実行場所・発生時刻を含む通知が届き、スタックトレースのファイルが添付される

#### Scenario: プレフィックスコマンドの例外の通知
- **WHEN** `%ping` の実行中に想定外の例外が発生する
- **THEN** エラーログチャンネルに、エラーの種類・メッセージ・元のメッセージ本文・実行場所・発生時刻を含む通知が届き、スタックトレースのファイルが添付される

### Requirement: 通知失敗時の継続
エラーログチャンネルへの通知自体が失敗した場合、bot はその失敗と元のエラーを標準出力のログに記録し、プロセスを停止せずに稼働を続けなければならない（SHALL）。

#### Scenario: ログチャンネルに送信できない
- **WHEN** エラーログチャンネルに送信権限がない状態で想定外エラーが発生する
- **THEN** 元のエラーと通知失敗の両方が標準出力に記録され、bot は以降のコマンドにも応答し続ける

### Requirement: コマンド外のエラーの記録
コマンドとリスナーの実行以外の箇所（Discord クライアントのエラーイベント、処理されなかった Promise の reject）で発生したエラーについて、bot は標準出力に記録し、エラーログチャンネルに通知しなければならない（SHALL）。

#### Scenario: 処理されなかった reject
- **WHEN** どこにも catch されない Promise の reject が発生する
- **THEN** 標準出力にエラーが記録され、エラーログチャンネルに通知が届く
