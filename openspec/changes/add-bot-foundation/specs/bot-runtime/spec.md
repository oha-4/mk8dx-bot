# Spec Delta

## Purpose

bot プロセスが設定を検証して Discord に接続し、スラッシュコマンドを登録・応答し、安全に停止するまでのライフサイクルを定める。

## ADDED Requirements

### Requirement: 起動時の設定検証
bot は起動時に必要な設定（bot トークン、アプリケーション ID、エラーログチャンネル ID、DB ファイルのパス）を検証しなければならない（SHALL）。必須の設定が欠けている、または形式が不正な場合、Discord に接続せずに非 0 の終了コードで終了し、どの設定が問題かをログに出力しなければならない（MUST）。秘密値そのものはログに出力してはならない（MUST NOT）。

#### Scenario: 必須設定が欠けている
- **WHEN** bot トークンを設定せずに bot を起動する
- **THEN** bot は Discord に接続せず非 0 で終了し、ログに欠けている設定名が出力される

#### Scenario: 設定の形式が不正
- **WHEN** エラーログチャンネル ID に数字以外の文字列を設定して起動する
- **THEN** bot は非 0 で終了し、ログにその設定名と期待する形式が出力される

#### Scenario: 秘密値をログに出さない
- **WHEN** 設定検証が失敗してログが出力される
- **THEN** ログに bot トークンの値は含まれない

### Requirement: スラッシュコマンドの登録
bot は起動時に、コードに定義されたスラッシュコマンドの一覧を Discord に登録しなければならない（SHALL）。開発用ギルド ID が設定されている場合はそのギルドにのみ登録し、設定されていない場合はグローバルに登録しなければならない（SHALL）。登録はコードの定義で全体を置き換える形で行い、コードから消えたコマンドは Discord からも消えなければならない（MUST）。

#### Scenario: 開発用ギルドへの登録
- **WHEN** 開発用ギルド ID を設定して bot を起動する
- **THEN** そのギルドでコードに定義されたコマンドが利用可能になり、グローバルコマンドは変更されない

#### Scenario: 削除したコマンドの反映
- **WHEN** コードからコマンドを 1 つ削除して bot を再起動する
- **THEN** 登録先からそのコマンドが消える

### Requirement: プレフィックスコマンド
bot はギルドのテキストチャンネルで、`%` または `％` で始まり、直後にコマンド名またはエイリアスが続くメッセージを、プレフィックスコマンドとして実行しなければならない（SHALL）。名前とエイリアスは大文字と小文字を区別して完全一致で照合し、名前より後ろの部分は空白で区切った引数として渡さなければならない（SHALL）。どのコマンドにも一致しないメッセージには応答してはならない（MUST NOT）。

#### Scenario: 全角のプレフィックスとエイリアス
- **WHEN** 利用者が、エイリアス `p` を持つ `ping` コマンドに対して `％p` と投稿する
- **THEN** `ping` コマンドが実行される

#### Scenario: 引数の受け渡し
- **WHEN** 利用者が `%ping a  b` と投稿する
- **THEN** `ping` コマンドに引数 `a` と `b` が渡される

#### Scenario: 一致しないプレフィックス
- **WHEN** 利用者が、どのコマンドにも一致しない `%unknown` を投稿する
- **THEN** bot は何も応答しない

### Requirement: メッセージリスナー
bot は、プレフィックスコマンドとして処理されなかったギルドのメッセージを、機能が登録したメッセージリスナーに渡さなければならない（SHALL）。プレフィックスコマンドとして処理したメッセージは、リスナーに渡してはならない（MUST NOT）。

#### Scenario: 通常メッセージがリスナーに届く
- **WHEN** メッセージリスナーが登録された状態で、利用者がプレフィックスのないメッセージを投稿する
- **THEN** そのメッセージがリスナーに渡される

#### Scenario: コマンドはリスナーに届かない
- **WHEN** 利用者が `%ping` を投稿する
- **THEN** `ping` コマンドが実行され、そのメッセージはリスナーに渡されない

### Requirement: bot のメッセージの無視
bot は、自身を含む bot アカウントと webhook が投稿したメッセージを、プレフィックスコマンドとしてもメッセージリスナーへの入力としても扱ってはならない（MUST NOT）。

#### Scenario: 他の bot の投稿
- **WHEN** 別の bot が `%ping` と投稿する
- **THEN** bot は応答せず、リスナーにも渡さない

### Requirement: 疎通確認コマンド
bot は疎通確認の `ping` コマンドを、スラッシュコマンド（`/ping`）とプレフィックスコマンド（`%ping`）の両方で提供し、Discord Gateway との往復遅延をミリ秒で応答しなければならない（SHALL）。スラッシュコマンドでは実行者にのみ見える形で、プレフィックスコマンドではそのチャンネルへの通常の投稿として応答しなければならない（SHALL）。

#### Scenario: スラッシュコマンドで ping
- **WHEN** 利用者が `/ping` を実行する
- **THEN** 実行者にのみ見えるメッセージで遅延のミリ秒値が返る

#### Scenario: プレフィックスコマンドで ping
- **WHEN** 利用者が `%ping` と投稿する
- **THEN** そのチャンネルに、返信ではない通常の投稿で遅延のミリ秒値が投稿される

### Requirement: 未知のコマンドへの応答
bot は自身が定義していないコマンドのインタラクションを受け取った場合、例外を発生させずに、実行者にのみ見える形で利用できない旨を応答しなければならない（SHALL）。

#### Scenario: 登録の反映前に古いコマンドが実行される
- **WHEN** bot が定義していない名前のコマンドインタラクションを受け取る
- **THEN** 実行者にのみ見えるメッセージで、そのコマンドが利用できない旨が返る

### Requirement: 安全な停止
bot は SIGTERM または SIGINT を受け取った場合、新しいインタラクションの受け付けを止め、DB 接続と Discord 接続を閉じてから終了コード 0 で終了しなければならない（SHALL）。停止処理が 10 秒以内に終わらない場合は強制的に終了しなければならない（MUST）。

#### Scenario: コンテナ停止
- **WHEN** 稼働中の bot に SIGTERM を送る
- **THEN** DB と Discord の接続が閉じられ、bot は終了コード 0 で終了する

#### Scenario: 停止処理が終わらない
- **WHEN** SIGTERM 受信後、停止処理が 10 秒以内に完了しない
- **THEN** bot は強制的に終了する
